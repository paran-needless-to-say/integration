# 멀티패턴 암호화폐 자금세탁 탐지 모델 재현 및 Rule-based AML 시스템 보완

## 1. 개발동기 및 목적

### 1.1 개발동기

암호화폐 시장은 지난 10년간 급속한 성장을 보이며 전 세계적으로 수조 달러 규모의 시장을 형성하였다. 그러나 이러한 성장과 함께 피싱, 해킹, 자금 세탁 등 불법 거래도 지속적으로 증가하고 있다. 특히 블록체인의 익명성 특성으로 인해 전통적인 금융 기관의 규제 시스템으로는 효과적인 탐지가 어렵다는 한계가 있다.

기존의 암호화폐 자금세탁 탐지 시스템들은 각각 한계점을 가지고 있다. **규칙 기반 시스템**은 해석 가능하고 빠르지만 복잡한 패턴을 놓칠 수 있으며, 새로운 공격 패턴에 대한 수동 룰 유지가 필요하다. **순수 머신러닝 접근법**은 높은 성능을 달성할 수 있지만 설명 가능성이 부족하고, 도메인 지식을 효과적으로 반영하기 어렵다. **그래프 기반 방법**은 강력한 패턴 탐지 능력을 가지지만 계산 비용이 높고 대규모 네트워크로 확장하기 어렵다. 기존의 **하이브리드 접근법**은 규칙 기반과 ML을 결합하지만, 두 구성 요소 간의 경계가 모호하고 최적화가 어렵다.

따라서 본 연구는 이러한 한계를 극복하기 위해, 규칙 기반 시스템의 해석 가능성과 머신러닝의 높은 성능을 동시에 제공하는 **2단계 하이브리드 아키텍처**를 제안하고자 한다.

### 1.2 개발목적

본 연구의 목적은 다음과 같다:

1. **2단계 하이브리드 리스크 스코어링 시스템 설계 및 구현**: 규칙 기반/그래프 통계 스코어링(1단계)과 머신러닝 기반 가중치 조정(2단계)을 명확하게 분리한 새로운 아키텍처를 제안하고 실제 시스템으로 구현한다.

2. **룰북 기반 Rule-based 시스템 구축**: Compliance, Exposure, Behavior 3축 룰 평가 시스템을 설계하고, 22개의 룰을 새로 정의하여 실제 코드로 구현한다. 특히 Multi-hop 분석을 통한 복잡한 세탁 패턴 탐지 능력을 강화한다.

3. **멀티패턴 탐지 능력 향상**: 그래프 기반 패턴 탐지(Layering Chain, Cycle, Fan-in/Fan-out), PPR(Personalized PageRank) 기반 간접 노출 탐지, 윈도우/버킷 기반 시간 패턴 탐지 등 다양한 세탁 패턴을 종합적으로 탐지할 수 있는 시스템을 구축한다.

4. **실제 데이터셋 기반 성능 검증**: 2016년부터 2024년까지 8년간 수집된 92,138개의 라벨링된 이더리움 거래 데이터셋을 활용하여 시스템의 성능을 검증하고, baseline 모델들과의 비교를 통해 우수성을 입증한다.

## 2. 개발내용

### 2.1 2단계 하이브리드 리스크 스코어링 시스템

본 연구에서 제안한 시스템은 명확하게 분리된 2단계 구조로 구성된다.

#### 2.1.1 1단계: Rule-Based + 그래프 통계 기반 스코어링

1단계에서는 본 연구에서 새로 설계한 룰북 기반 규칙 평가와 그래프 통계 분석을 결합한다. 각 트랜잭션에 대해 22개의 룰을 평가하여 규칙 기반 점수를 계산하고, 동시에 거래 네트워크의 구조적 특성(노드 수, 엣지 수, 밀도, 클러스터링 계수 등)을 분석하여 그래프 통계 점수를 생성한다. 최종적으로 규칙 기반 점수(90%)와 그래프 통계 점수(10%)를 가중 결합하여 1단계 점수를 산출한다.

**구현 내용:**

- 룰북 YAML 정의 파일 작성 (22개 룰)
- 룰 평가 엔진 구현 (`core/rules/evaluator.py`)
- Compliance(C), Exposure(E), Behavior(B) 3축 룰 분류
- 윈도우 룰 평가기 구현 (시간 기반 패턴 탐지)
- 버킷 룰 평가기 구현 (시간 버킷 기반 집계)
- Topology 룰 평가기 구현 (그래프 구조 패턴 탐지)
- 그래프 통계 계산기 구현 (NetworkX 기반)

#### 2.1.2 2단계: 머신러닝 기반 가중치 조정 및 최종 스코어링

2단계에서는 1단계에서 생성된 점수와 추가적인 그래프 features를 입력으로 받아 머신러닝 모델(Gradient Boosting Classifier)을 통해 최종 리스크 점수를 조정한다. 이를 통해 1단계의 규칙 기반 점수만으로는 포착하기 어려운 복잡한 패턴을 학습하고, 최종 정확도를 향상시킨다.

**구현 내용:**

- 40차원 feature 공간 설계 (규칙 점수, 그래프 통계, PPR features, 상호작용 features 등)
- 앙상블 모델 구현 (Voting Classifier: Gradient Boosting + Random Forest + Logistic Regression)
- 하이퍼파라미터 최적화 (GridSearchCV를 통한 체계적 탐색)
- Threshold 최적화 (최적 임계값 0.42로 조정)
- 클래스 불균형 처리 (class_weight='balanced')
- 모델 저장 및 로드 시스템

### 2.2 룰북 설계 및 구현

본 연구에서 새로 설계한 룰북은 블록체인 주소의 리스크를 평가하기 위한 22개의 룰로 구성되며, 각 룰은 C(Compliance), E(Exposure), B(Behavior) 3가지 축으로 분류된다.

#### 2.2.1 Compliance(C) 축 룰

규정 준수 관련 리스크를 평가한다:

- **C-001**: Sanction Direct Touch (제재 주소 직접 거래) - 30점
- **C-002**: High-Risk Jurisdiction VASP (고위험 관할권 VASP 거래) - 20점
- **C-003**: High-Value Single Transfer (고액 단일 거래) - 25점
- **C-004**: High-Value Repeated Transfer (24시간 내 고액 반복 거래) - 20점

#### 2.2.2 Exposure(E) 축 룰

위험 요소에 대한 직접적/간접적 노출을 평가한다:

- **E-101**: Mixer Direct Exposure (믹서 직접 노출) - 32점
- **E-102**: Indirect Sanctions Exposure (간접 제재 노출, PPR 기반) - 39점
- **E-103**: Counterparty Quality Risk (상대방 품질 리스크) - 19점
- **E-104**: Bridge Direct Exposure (브릿지 직접 노출) - 19점
- **E-105**: Scam Direct Exposure (사기 주소 직접 노출) - 26점

#### 2.2.3 Behavior(B) 축 룰

의심스러운 행동 패턴을 평가한다:

- **B-101**: Burst (10분 내 2회 이상 거래) - 15점
- **B-102**: Rapid Sequence (1분 내 3회 이상 거래) - 20점
- **B-103**: Inter-arrival Std High (거래 간격 표준편차 높음) - 10점
- **B-201**: Layering Chain (3-hop 이상 레이어링 체인) - 25점
- **B-202**: Cycle (2-3 hop 순환 구조) - 30점
- **B-203**: Fan-out (10분 버킷 내 다수 주소로 분산) - 20점
- **B-204**: Fan-in (10분 버킷 내 다수 주소에서 집중) - 20점
- **B-501**: High-Value Buckets (동적 점수, 3-30점)
- **B-502**: Structuring (반올림된 금액 반복) - 10점

**구현 현황:**

- Basic 모드: 18개 룰 활성 (1-hop 분석)
- Advanced 모드: 20개 룰 활성 (3-hop 분석, 그래프 패턴 탐지 포함)
- 미구현: 4개 룰 (State 룰, 주소 생명주기 정보 필요)

### 2.3 Multi-hop 그래프 분석

복잡한 자금 세탁 패턴을 탐지하기 위해 Multi-hop 그래프 분석을 구현하였다. 주소의 거래 관계를 재귀적으로 추적하여 1-hop(직접 거래), 2-hop, 3-hop까지의 거래 네트워크를 구축하고 분석한다.

**구현 내용:**

- NetworkX 기반 그래프 구축 및 분석
- Multi-hop 거래 추적 알고리즘
- 그래프 패턴 탐지:
  - **Layering Chain**: 다층 구조의 자금 이동 탐지
  - **Cycle**: 순환 구조의 거래 탐지
  - **Fan-in/Fan-out**: 자금 집중/분산 패턴 탐지
- PPR(Personalized PageRank) 알고리즘을 통한 간접 제재 노출 탐지

### 2.4 두 가지 분석 모드 제공

실제 운영 환경의 다양한 요구사항을 충족하기 위해 두 가지 분석 모드를 제공한다.

**Basic 모드 (1-hop):**

- 빠른 응답 시간 (1-5초)
- 18개 룰 활성화
- 실시간 대시보드에 적합
- 계산 비용 최소화

**Advanced 모드 (3-hop):**

- 정밀 분석 (15-30초)
- 20개 룰 활성화 (그래프 패턴 탐지 포함)
- 복잡한 세탁 패턴 탐지 가능
- 정확도 30-50% 향상

### 2.5 API 시스템 구현

실시간 주소 분석을 위한 RESTful API를 구현하였다.

**주요 엔드포인트:**

- `POST /api/analyze/address`: 주소 기반 리스크 분석 (다중 트랜잭션)
- `GET /health`: 서버 상태 확인
- `GET /api-docs`: Swagger UI 기반 API 문서

**기능:**

- JSON 형식의 요청/응답 처리
- 트랜잭션 데이터 변환 및 검증
- 비동기 분석 처리
- 에러 처리 및 로깅

## 3. 주요기술

### 3.1 그래프 분석 기술

**NetworkX 라이브러리:**

- 블록체인 거래 네트워크를 방향성 그래프로 모델링
- 그래프 구조 분석 메트릭 계산 (노드 수, 엣지 수, 밀도, 클러스터링 계수 등)
- 그래프 패턴 탐지 알고리즘 구현

**Personalized PageRank (PPR):**

- 특정 주소(제재 주소)와의 간접적 연결성을 측정
- 2-hop 이내의 노출 위험도 정량화
- 그래프 기반 근접성 점수 계산

### 3.2 머신러닝 기술

**Gradient Boosting Classifier:**

- 앙상블 학습 방법을 통한 높은 예측 성능
- Feature 중요도 분석으로 해석 가능성 확보
- 클래스 불균형 데이터 처리

**Feature Engineering:**

- 규칙 기반 features (룰 점수, 룰 축별 점수, 심각도 분포)
- 그래프 통계 features (노드 수, 엣지 수, 밀도 등)
- PPR features (간접 노출 점수)
- 시간 기반 features (거래 간격, 버스트 패턴 등)
- 상호작용 features (rule_score × graph_score 등)
- Fan-in/out 비율, 그래프 밀도, Rule 다양성 등
- 총 40차원 feature 공간 구성 (30차원에서 확장)

**하이퍼파라미터 최적화:**

- GridSearchCV를 통한 체계적 탐색
- 최적 파라미터: n_estimators=200, max_depth=5, learning_rate=0.2, subsample=1.0, min_samples_split=10
- Cross-validation 점수: 0.9867
- Cross-validation을 통한 일반화 성능 확보

**앙상블 모델:**

- Voting Classifier를 활용한 Soft Voting 앙상블
- Gradient Boosting + Random Forest + Logistic Regression 결합
- 앙상블을 통한 성능 향상 및 안정성 확보

### 3.3 규칙 기반 시스템 기술

**YAML 기반 룰 정의:**

- 룰을 코드와 분리하여 유지보수성 향상
- 룰의 동적 수정 및 확장 가능
- 룰 메타데이터 관리 (축, 심각도, 점수 등)

**윈도우 기반 시간 패턴 탐지:**

- 슬라이딩 윈도우 알고리즘
- 시간 기반 집계 및 그룹화
- 쿨다운 메커니즘을 통한 중복 발동 방지

**버킷 기반 집계:**

- 고정 시간 버킷으로 거래 분할
- 다중 필드 기반 그룹화 (체인, 토큰, 주소 등)
- 집계 조건 평가 (합계, 횟수, 고유값 개수 등)

### 3.4 데이터 처리 기술

**데이터 변환 및 검증:**

- 트랜잭션 데이터 형식 표준화
- 필수 필드 검증
- 데이터 타입 변환 및 정규화

**성능 최적화:**

- 그래프 구축 및 분석 최적화
- 룰 평가 순서 최적화 (단일 트랜잭션 → 집계 룰)
- 캐싱 메커니즘 (리스트 로딩, 그래프 구조 등)

### 3.5 소프트웨어 아키텍처

**모듈화 설계:**

- 룰 평가 엔진 (`core/rules/`)
- 그래프 분석 (`core/aggregation/`)
- 스코어링 엔진 (`core/scoring/`)
- API 라우터 (`api/routes/`)

**의존성 관리:**

- Python 3.10+ 기반
- requirements.txt를 통한 패키지 관리
- 가상 환경(virtualenv) 지원

## 4. 결과 및 분석

### 4.1 데이터셋

본 연구는 Graph of Graphs (GOG) 논문의 연구자들이 수집한 데이터셋을 활용하였다. 실험을 위해 이더리움 데이터에 집중하였으며, 최종적으로 92,138개의 라벨링된 거래 데이터를 사용하였다.

**데이터 출처:**

- 이더리움: 14,464개 토큰, 81,788,211개 거래, 10,247,767개 주소 (2016-02 ~ 2024-02)

**라벨링 방법:**

- Etherscan 주소 태그에서 파생
- 사기 라벨 (label=1): 피싱, 해킹, 스캠 태그
- 정상 라벨 (label=0): 금융 태그, 밈 태그, 태그 없음

**데이터셋 분할:**

- 전체: 92,138개 (정상 58.1%, 사기 41.9%)
- 학습용 샘플링 데이터셋 (5,000개):
  - 학습 (Train): 3,499개 (70%)
  - 검증 (Validation): 749개 (15%)
  - 테스트 (Test): 752개 (15%)
- 계층적 샘플링으로 라벨 분포 유지

### 4.2 성능 결과

#### 4.2.1 1단계 성능 (규칙 기반 + 그래프 통계)

1단계만으로는 제한된 성능을 보였으며, 2단계 ML 정제의 필요성을 나타냈다.

**최적화된 구성:**

- Rule weight: 0.9
- Graph weight: 0.1
- Threshold: 39.0

**결과:**

- Accuracy: 38.70%
- F1-Score: 0.4287
- ROC-AUC: 0.4508

#### 4.2.2 2단계 성능 (최적화 후)

2단계 ML 기반 가중치 조정 및 성능 최적화를 통해 성능이 크게 향상되었다.

**최적화 방법:**

1. **하이퍼파라미터 최적화**: GridSearchCV를 활용하여 Gradient Boosting Classifier의 최적 파라미터 탐색

   - `n_estimators=200`, `max_depth=5`, `learning_rate=0.2`, `subsample=1.0`, `min_samples_split=10`
   - Cross-validation 점수: 0.9867

2. **앙상블 모델**: Voting Classifier를 활용하여 Gradient Boosting + Random Forest + Logistic Regression의 Soft Voting 앙상블 구현

3. **고급 Feature Engineering**: 30차원에서 40차원으로 확장

   - 상호작용 Features (rule_score × graph_score) 추가
   - Fan-in/out 비율, 그래프 밀도, Rule 다양성 등 추가

4. **Threshold 최적화**: 기본 0.5에서 최적 0.42로 조정하여 F1-Score 최대화

**최종 결과 (Test Set):**

- **Accuracy: 99.20%** (+60.50%p 개선, 1단계 대비)
- **Precision: 0.9968** (False Positive 비율 0.32%)
- **Recall: 0.9841**
- **F1-Score: 0.9904**
- **ROC-AUC: 0.9992** (거의 완벽한 판별력)

**검증 결과 (Validation Set):**

- Accuracy: 99.47%
- Precision: 0.9968
- Recall: 0.9904
- F1-Score: 0.9936
- ROC-AUC: 0.9991

**과적합 검증**: Validation(99.47%)과 Test(99.20%) 성능 차이가 0.27%p에 불과하여 과적합이 없음을 확인

## 5. 활용방안 및 기대효과

### 5.1 활용방안

#### 5.1.1 중앙화 거래소(CEX) 적용

본 시스템은 중앙화 거래소에서 실시간으로 사용자 입출금 주소의 리스크를 평가하는 데 활용될 수 있다. 새로운 사용자가 입금 주소를 등록할 때, 또는 기존 사용자의 거래 히스토리를 주기적으로 모니터링할 때 자동으로 리스크 점수를 계산하여 의심스러운 주소를 사전에 차단할 수 있다.

**구체적 활용 시나리오:**

1. **입금 주소 사전 검증**: 사용자가 입금 주소를 등록할 때 실시간으로 리스크 점수 계산
2. **출금 거래 승인 전 검증**: 출금 요청 시 상대방 주소의 리스크 점수 확인
3. **주기적 모니터링**: 기존 사용자의 거래 패턴 변화를 주기적으로 분석하여 리스크 재평가
4. **규제 기관 보고**: 높은 리스크 점수를 받은 주소 및 거래를 자동으로 규제 기관에 보고

#### 5.1.2 지갑 서비스 제공업체 적용

암호화폐 지갑 서비스 제공업체에서도 본 시스템을 활용할 수 있다. 사용자가 특정 주소로 자금을 전송하려고 할 때 실시간으로 리스크 경고를 제공하거나, 자동으로 차단하는 기능을 구현할 수 있다.

#### 5.1.3 규제 기관 및 법집행기관 적용

규제 기관과 법집행기관에서는 대규모 블록체인 데이터를 분석하여 의심스러운 거래 패턴을 탐지하는 데 본 시스템을 활용할 수 있다. 특히 OFAC SDN 리스트 기반 제재 주소 탐지 기능은 규제 업무에 직접적으로 활용 가능하다.

#### 5.1.4 연구 및 학술적 활용

본 시스템의 구현 코드와 데이터셋은 향후 암호화폐 자금세탁 탐지 연구에 활용될 수 있다. 특히 2단계 하이브리드 아키텍처와 본 연구에서 설계한 룰북은 관련 연구의 베이스라인으로 활용 가능하다.
